# Деплой GONKA.BLOG

Сайт — статическая сборка Astro. Сервер VDS #1 обслуживает `gonka.blog` и `www.gonka.blog` через nginx. На 6 ноября 2026 года nginx читает `/var/www/gonka-blog-landing/current`, который указывает на каталог в `releases/`. Старая ссылка `frontend` не является активным корнем сайта.

Исходники и контент админки находятся на сервере в `/var/www/gonka-blog-landing/source`. Админка `admin.gonka.blog` работает как процесс PM2 `admin-gonka-blog`; её публикация собирает сайт из этого каталога и переключает `current` на новый релиз. Перед работой сверяйте фактическое состояние сервера: содержимое, добавленное через админку, может быть новее GitHub и локальной копии.

## Публикация контента

1. В админке сохраните изменённый раздел кнопкой «Сохранить черновик».
2. Нажмите «Опубликовать» и дождитесь подтверждения.
3. Проверьте изменённый раздел на сайте. Для записей с будущей датой после её наступления нужна новая публикация: сайт статический.

Файлы новостей хранятся в `source/public/news-media` и должны попадать в релиз вместе с JSON. Экспорт JSON сам по себе не заменяет резервную копию загруженных файлов.

## Деплой изменений кода

- Снимите фактические адреса `current`, конфигурацию nginx, состояние админки и контрольные суммы данных и загруженных файлов. Сохраните предыдущий релиз и резервную копию исходников, включая конфигурацию и данные админки.
- Аккуратно объедините серверные данные с изменениями кода. Не заменяйте файлы пользователя устаревшей локальной копией. Синхронизируйте код и данные админки с релизом, иначе её следующая публикация вернёт старую версию.
- Соберите проект вне production-сервера (`npm run build`), запустите `npm test`, `npm run check:bindings`, `npm run verify:dist`. Доставьте результат в новый отдельный каталог `releases/`, проверьте целостность и наличие `index.html`.
- Непосредственно перед переключением убедитесь, что данные, загруженные файлы и активный релиз не изменились с момента снимка. Переключите `current` атомарной заменой симлинка. Проверьте главную, ассеты, админку и соседние сайты; сохраните возможность возврата к предыдущему релизу и исходникам.
- Не используйте старую команду `rsync --delete` к `frontend` или `current`. Не меняйте DNS, nginx и соседние сервисы без необходимости.

Для отката укажите `current` на заранее записанный предыдущий каталог релиза атомарной заменой симлинка. Если менялся код админки, восстановите совместимую резервную копию исходников и перезапустите процесс PM2; не теряйте изменения контента, внесённые после снимка.

Репозиторий: https://github.com/textsmen-design/gonka-blog-creative-lab. Пароли, токены и хеши паролей в Git не добавляются. Коммит GitHub не обновляется автоматически после каждого изменения через админку: перед синхронизацией сначала сверьте серверный контент и медиа.
